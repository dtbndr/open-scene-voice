# Release notes

Changes that users of the `scenevoice` command will notice. Backward compatibility is not kept between releases; anything that changes how you run a command is listed here.

## 0.2.0 (2026-11-25)

Changes since 0.1.0 (published 2026-11-09).

### New

- `scenevoice beats SCRIPT --model M --out FILE` splits each scene into visual beats with one OpenRouter call and writes a JSON sidecar file. The sidecar records the script's SHA-256 and is never part of the script, the plan, the pack or the timeline. It never overwrites an existing file. If the reply cannot be used, the cleaned raw reply is written instead and the command exits 1; the call may still have been charged.
- `scenevoice keys status|set|remove` manages a per-user key file, so keys no longer have to live in a `.env` file in the folder you run from. `set` reads the value from standard input, never from the command line. `status` prints which keys are saved as one JSON line.
- The key file is `~/.config/scenevoice/keys.env` (also on macOS), or `$XDG_CONFIG_HOME/scenevoice/keys.env` when that is set, or `%APPDATA%\scenevoice\keys.env` on Windows. `SCENEVOICE_KEYS_FILE` overrides the location. Its folder is created with mode 0700 and the file with 0600; looser permissions print a `NOTE` and the file is still used.
- Each key is taken from the process environment first, then the key file, then `./.env`; a blank value falls through to the next source. A key file that cannot be read or has a malformed line fails the run, even when the environment supplies every key. `align` does not read the key file when every scene comes from `synth_record.json`.
- `docs/script-format.md` ends with "Starting from an idea": paste the guide and your idea into any chat assistant to get a first draft in the script format.
- `--progress json` on `plan`, `synth`, `align`, `pack` and `beats` writes one JSON object per stderr line. `synth` and `align` report each scene as started and done, and a failure is a `fail` event with `kind`, `scene`, `line` and `status`. `--progress text`, the default, is unchanged.
- `scenevoice web` starts a local server on `127.0.0.1` at a fixed port (47615) and opens your browser on a link that carries a secret token for that launch; a link from an earlier launch shows a page telling you to start `scenevoice web` again. The page it opens is described in the next bullets. `--port N` (1024 to 65535) picks another port, and `--no-open` prints the link without opening the browser. If another SceneVoice is already running on that port, the command says so and exits 1. Press Control-C to stop (any job that is running is stopped first). `python -m scenevoice` runs the same program as the `scenevoice` command.
- The page `scenevoice web` opens now has a Keys page and a project list. On Keys you add, replace or remove the Google Cloud, ElevenLabs and OpenRouter keys; a saved key is never shown back, and the project ID and region are shown. The first time you open it with no key and no project, it takes you to Keys once (Skip for now goes on to Projects). Projects lists your projects, newest first, and makes a new one from a name. Opening a project opens its script editor, described below. If you close the Terminal window, or open a link from an earlier run, the page tells you to start `scenevoice web` again.
- Under `web`, the key precedence above does not apply: environment key variables and `./.env` are ignored, and only the key file is used. The launch message names any key variables it is ignoring; add the keys with `scenevoice keys set`.
- `scenevoice web` now keeps your scripts as projects in a `SceneVoice` folder inside your Documents folder, one folder per script. The folder is created when you make your first project. Set `SCENEVOICE_WORKSPACE` to an absolute path (for example `/Users/you/Scripts`) to use another folder; a relative path makes `web` refuse to start. On macOS you may be asked to allow access to Documents the first time SceneVoice looks at the folder, no later than the first time it lists your projects.
- A script saved through `web` can be about 60 KB at most; a longer one is refused. Project folders you make by hand are not listed unless their name uses only lowercase letters, digits and hyphens (capital letters and spaces are not listed), so let SceneVoice make the folders.
- The key file cannot live inside the workspace folder: if `SCENEVOICE_KEYS_FILE` points into it, `scenevoice web` refuses to start and says so. Files with more than one hard link are not played, saved over or zipped. The zip of a packed project holds the manifest, the timeline and the audio only, never the script or other working files.
- `scenevoice web` can now run the work itself, one job at a time: voice a script (all scenes, the scenes still missing, or Start again), redo one scene, update line markers, pack, and plan visual beats (and redo them). A second start while a job runs is refused with "SceneVoice is busy ...". Progress arrives scene by scene and a job can be cancelled; a cancelled run may still be charged by the provider. The scenes already voiced stay.
- Before it spends anything, the server checks the numbers you confirmed (scenes, characters, model and the script itself) against the saved script, so a script that changed after you looked is refused with a request to confirm again.
- Start again keeps your old audio, line markers and pack until the first new scene has finished; then the old audio, line markers and pack are deleted. A run that ends before that puts the old files back. If they cannot be put back they stay in the project folder in files that start with `.write-restart`; do not delete them.
- A pack run replaces the old pack first: if it fails or is cancelled, the old manifest and timeline are gone and you pack again. Redo beats keeps the old beats until the new set passes its check; a reply the CLI cannot read as beats is thrown away (the call is still charged).
- Saving a script, and downloading the zip, are refused while a job runs, in any project; a job start is refused for the moment a download is being prepared ("SceneVoice is busy preparing a download."); try again. Closing the Terminal window, `kill` and Control-C all stop the running job and wait for it before the server exits (a hard kill may leave one job to finish).
- The page `scenevoice web` opens now has a script editor and a beats screen. A project opens on a text box where you paste a script or upload a file (over 1 MiB, or not plain UTF-8, is refused and the box is left as it was). Save keeps the script as written, even with a problem in it. It is checked when you press Save and after a short pause in typing: the check is free, it shows the first problem only ("Show line N" jumps to it), and it never changes your words. Leaving with unsaved changes asks first. A script with Windows-style line endings or a hidden marker at the start opens as an unsaved change; saving fixes it, and the words do not change. "Script guide" opens an in-app page, built from `docs/script-format.md`, in a new tab.
- Beats in the browser: a "Plan visual beats" link under the editor opens the beats screen. You type the OpenRouter model name (there is no preset), the page shows the cost confirmation before anything is spent, and if the OpenRouter key is not saved it opens the key popup first and then the confirmation. While planning you can Cancel ("Stopping..." until it has really stopped); a cancelled run may still be charged. The finished list shows each scene with its beats as sentence numbers and a note, and "Redo beats" asks again; a failed redo keeps the old list. If the script changes after the beats were made, a banner says the beats are out of date. Beats are limited to scripts of 20,000 characters, and the page says so before it asks you to confirm.
- `scenevoice web` has a read-only route that returns a project's saved beats, but only when the file passes a light shape check; a damaged beats file shows a plain message on the beats screen instead of a list.
- Beats failures are in plain words, one message for each case that needs a different next step: no key or a refused key, no credit, too many requests, OpenRouter down, no answer in time, request refused, unusable reply, could not finish, an input problem such as a script that is too long, and cancelled. Cases that cannot be told apart (a reply held back, empty or unreadable, or cut off) share two messages (unusable reply, could not finish) and make no claim about charges. Try again always sends a new paid request after a new confirmation.
- The page never stores a key or the launch token in the browser (no `localStorage`, and no app code uses `sessionStorage`; SvelteKit keeps its own scroll numbers there).
- Every job the web server runs now has a run id (the `run` field of the job status). Cancel must name it (`POST /api/jobs/current/cancel` with `{"run": "..."}`): a missing or malformed id is refused, and a cancel for a run that has already ended says "That voicing run has already ended, so nothing was stopped." `GET /api/jobs/current?run=ID` answers for that run, live or its last result. The browser's beats screen cancels only the run it started itself.
- Voice and review in the browser: a "Next: Voice" button on the script editor and on the beats screen opens the voice screen, where you pick a voice and a model (the lists come from the CLI itself), see the cost confirmation, and start voicing. A progress view shows each scene as it finishes, with a play button and a Cancel button. A run that stops part-way offers "Voice the rest" and "Start again" and says which scenes were kept. A failed run gives one plain message for each kind of failure. The Review screen plays one scene at a time and has "Redo this scene" with its own confirmation. "Next: Pack" opens the Pack screen (described in the Pack bullet below). Scene text, the scene strip and durations are not shown.
- There is now an install guide for people who do not write code: [`docs/install.md`](install.md). It installs SceneVoice with `uv tool install --python 3.12`, so SceneVoice runs on the Python version it is tested with.
- Pack in the browser: "Next: Pack" on the Review screen opens "Pack for DaVinci Resolve". It shows the line-marker status ("Not made yet", "Up to date", or which scenes changed) with an "Update line markers" button, and a "Pack for Resolve" button. Updating line markers is free for scenes voiced with ElevenLabs and runs without a question; for scenes voiced with Gemini each scene is listened to by OpenRouter, so the page opens the key popup first when the OpenRouter key is missing, then asks "N scenes will be listened to" before it spends anything. You can Cancel an update; a stopped update may have saved the markers or may not, so the page tells you to check the line-marker status and warns that a scene being listened to may still have used quota. A failed update saves nothing, and the page says you can also pack without updating the line markers. Packing is free and has no Cancel. Once packed, the page lists the files, with "Show in Finder" (macOS and Linux only) and "Download as zip". The "Done" text says the files are in your Documents folder, which is not true when you started `scenevoice web` with another workspace folder.

### Fixed

- The installed program no longer fails at start-up with a missing `dotenv` module.
- If macOS refuses SceneVoice access to your Documents folder, the page now says so and tells you where to allow it (System Settings, Privacy and Security, Files and Folders), instead of "Something went wrong.". The same message appears if `SCENEVOICE_WORKSPACE` points at a folder SceneVoice cannot read.
- `beats` now accepts a reply wrapped in a code fence that follows blank lines, which it used to treat as unusable.
- In the browser, saving a missing key after a partly voiced run no longer leaves the voice screen with no voice choice picked.

### Changed

- `plan` error messages are in plain words. The rules, their order and the one-error-at-a-time behaviour are unchanged, and the frame `scenevoice plan: FAIL FILE: MESSAGE (line N)` is the same.
- Missing-key failures in `synth`, `align` and `beats` now say `Missing: NAME. Add it with "scenevoice keys set NAME", or put it in KEY_FILE.`
- A path argument that is not a regular file (for example `/dev/stdin`, a `<(...)` process substitution or a named pipe) is refused as "not a regular file" by `plan`, `synth`, `align`, `pack` and `beats`. To read a plan from standard input, leave out the PLAN argument.
- Provider error excerpts (Vertex, ElevenLabs, OpenRouter) remove the key before the 500-character cut, so no part of a key can survive at the cut. An error body with non-ASCII text now shows up to 500 characters, where it showed fewer before.
- The `align` usage line now shows `[--progress {text,json}]`.

### Removed

- `docs/specs/script-contract.md`. `docs/script-format.md` is the script guide, and the tests are the authority for the script rules.
